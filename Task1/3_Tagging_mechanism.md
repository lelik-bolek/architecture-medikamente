# 1. Схема и таксономия тегов для «Медикаменте»

Для однозначной классификации данных клиники вводим три взаимодополняющие категории тегов:

## Категория 1: Тип конфиденциальности (Sensitivity Level)

* `TAG:CONFIDENTIAL-PHI` (Protected Health Information) — специальные категории медицинских данных: диагнозы, анамнез, назначения, результаты анализов. Доступ разрешён исключительно лечащим врачам.


* `TAG:CONFIDENTIAL-PII` (Personally Identifiable Information) — персональные данные субъекта: ФИО, телефон, email, паспорт, адрес. Доступ ограничен регистратурой и кассой в рамках их функционала.


* `TAG:FINANCIAL` — сведения об оплатах, транзакциях, кассовых чеках и взаиморасчётах (доступно кассирам и бухгалтерии).


* `TAG:INTERNAL-OPERATIONAL` — внутрикорпоративные служебные данные: график работы кабинетов, инвентарные номера оборудования, справочники услуг (открыто для сотрудников).



## Категория 2: Слой обработки данных (Data Layer)

* `TAG:LAYER-RAW` — сырые исходные данные (непроверенные выгрузки, входящие пакеты от МФУ).


* `TAG:LAYER-PROCESSED` — верифицированные и очищенные рабочие записи внутри операционных сервисов.


* `TAG:LAYER-GOLDEN-RECORD` — эталонные профили пациентов («золотой источник» / Single Source of Truth).


* `TAG:LAYER-ANALYTICS` — деперсонализированные и агрегированные массивы для отчётов, BI и обучения алгоритмов.



## Категория 3: Статус согласия субъекта (Consent Status)

* `TAG:CONSENT-MED-GRANTED` — зафиксировано явное согласие на медицинское вмешательство и обработку специальных ПДн.


* `TAG:CONSENT-MARKETING-GRANTED` — получено отдельное согласие на информационные рассылки и уведомления.


* `TAG:CONSENT-REVOKED` — согласие отозвано; триггер для немедленной блокировки и планового удаления данных.

## 2. Выбор платформенных инструментов

Исходя из целей компании: пятикратное масштабирование, медицинский профиль и открытый исходный код и стек команды (Java, Postgres, ClickHouse, Kubernetes, Active Directory):

1. **Инструмент обнаружения, инвентаризации и каталогизации данных:**

* **Выбор: Apache Atlas**.
* *Обоснование из курса:* Apache Atlas — зрелое open-source решение для управления метаданными, классификации и визуализации Data Lineage. В отличие от коммерческих платформ (BigID, Collibra, OneTrust), которые крайне дороги в лицензировании и сложны в поддержке для развивающейся клиники, Atlas не требует лицензионных затрат, легко разворачивается в инфраструктуре компании и автоматизирует назначение тегов на уровне таблиц и столбцов.

1. **Инструмент управления доступом на основе тегов (Policy Engine):**

* **Выбор: Apache Ranger** (в интеграции с Keycloak / Active Directory).
* *Обоснование из курса:* Apache Ranger нативно интегрируется с Apache Atlas, позволяя настроить контроль доступа на основе тегов (Tag-based Authorization). Если Atlas пометил колонку тегом `PHI`, Ranger автоматически блокирует её чтение для всех ролей, кроме врачей, независимо от того, через какой сервис идёт обращение к базе данных.

3. **Инструмент оркестрации и защиты потоков данных:**

* **Выбор: Apache NiFi**.
* *Обоснование из курса:* Позволяет автоматизировать движение данных между системами, на лету выполняя обогащение метаданными (тегирование), динамическую маршрутизацию по тегам и шифрование потоков по TLS.
